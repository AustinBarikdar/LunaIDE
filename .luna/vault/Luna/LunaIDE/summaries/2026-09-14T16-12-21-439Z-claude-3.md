Fixed the two CPU-burn issues in `VaultGraph.tsx`'s canvas animation:

1. **RAF loop now stops when settled.** `loop()` checks `alpha <= 0.06 && !drag.current` after each `step()+draw()`; if true it sets `raf = 0` and returns instead of rescheduling. A `wake(resetAlpha)` function (stored in a ref so JSX handlers can reach it) resets `alpha = 1` and restarts the loop when a drag begins (`onMouseDown`). Graph-data changes already tear down and recreate this whole effect (deps `[graph]`), so they naturally restart the loop with `alpha = 1` — no extra code needed there.
2. **Hover highlighting still repaints while stopped.** Hover state doesn't drive physics, so it doesn't need the continuous loop — but it still needs a redraw. The existing `hoverRef` sync effect now also calls a `redraw()` ref (bound to the same `draw` closure) whenever `hover` changes, giving an instant single repaint with no physics tick, whether or not the RAF loop is currently running.
3. **`getComputedStyle('--fg')` is no longer called every frame.** It's read once when the effect mounts and cached in `fgRgb`. The app already dispatches a `window.dispatchEvent(new Event('luna:theme'))` on every theme change (`theme.ts`), so I added a listener for `luna:theme` that recomputes `fgRgb` and does one redraw — no new mechanism, reused the existing one.

No visual/behavioral change: dragging, hover tooltips/edge highlighting, and double-click-to-open all still work — dragging always resumes the loop at full `alpha`, exactly like the previous always-on loop did during interaction. `npm run typecheck` and `npm test` both pass (24/24).
