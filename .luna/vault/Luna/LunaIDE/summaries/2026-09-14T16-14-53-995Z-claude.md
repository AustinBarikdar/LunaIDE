title: Fixed two performance issues: keystroke re-renders and a never-stopping canvas loop
---

Audited the renderer for perf issues and found two real ones, delegated a fix for each, verified both (typecheck clean, 24/24 tests pass).

**1. Every keystroke in the code editor re-rendered the entire app window.** `Editor.tsx`'s CodeMirror `onChange` pushed each keystroke straight into `App.tsx`'s `files` state, and nothing in the tree was memoized — so typing re-rendered the sidebar, tabs, terminals, and status bar on every character. Fixed by buffering edits locally and committing to app state ~200ms after typing pauses, flushing immediately on tab close/app quit so no keystrokes are lost, and reading live content straight from the CodeMirror view on save (Cmd+S) so a save mid-debounce never misses the latest text.

**2. The Vault Graph's cursor position also lived in `App.tsx` state**, so moving the mouse over the graph re-rendered the whole app too — even though a store (`editorStore.ts`) already existed to solve exactly this, it just wasn't wired up anywhere. Finished wiring it: `StatusBar` now reads cursor position directly from that store instead of via an App-level prop.

**3. The Vault Graph's physics/render loop never stopped.** Its `requestAnimationFrame` loop kept ticking forever at full framerate even after the graph settled and nobody was looking at it, and it recomputed a CSS color via `getComputedStyle` on every single frame. Fixed by stopping the loop once settled (waking it on drag or graph changes) and caching the color, refreshing it only on theme toggle.

Files changed: `src/renderer/src/components/Editor.tsx`, `src/renderer/src/App.tsx`, `src/renderer/src/components/StatusBar.tsx`, `src/renderer/src/components/VaultGraph.tsx`.
