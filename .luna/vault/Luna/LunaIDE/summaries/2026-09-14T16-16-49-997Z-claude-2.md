title: Debounce editor keystrokes out of App state (fix full-app re-render on typing)
---

Root cause: `Editor.tsx`'s CodeMirror `onChange` called `setFiles` (App-level state) on every keystroke, re-rendering the whole tree (sidebar, tabs, terminals, VaultGraph — none memoized).

Fix, following the `editorStore.ts` out-of-React-store pattern already in this repo and the debounce idiom already used in `lspExtensions.ts`'s LSP change sync:

- `Editor.tsx`: `onChange` now buffers the latest value in a ref (`pendingEdit`) and only calls `setFiles` ~200ms after typing pauses (`flushEdit`). Flushed early on: tab switch/unmount (existing `[activePath]` cleanup effect), `beforeunload`, and clicking "Clear diff" (same file path remounts CodeMirror, so the `[activePath]`-only effect wouldn't otherwise catch it).
- `App.tsx`'s `saveActive` (Cmd+S) no longer trusts `files[].content`, which can now lag ~200ms behind real typing. It reads the live document straight from the mounted CodeMirror view via the already-exported `viewFor(path)` (from `lspExtensions.ts`), falling back to `file.content` if the view isn't mounted. This guarantees Cmd+S never saves stale content regardless of debounce timing.

Verified: `npm run typecheck` and `npm test` (24/24) pass. `eslint` on the two touched files: 0 errors, 2 pre-existing-style `exhaustive-deps` warnings (intentional — `flushEdit` reads from refs so omitting it from deps is safe, same tradeoff CodeMirror/ref-based effects make elsewhere).

Known/accepted tradeoffs (flagging per the task's ask):
- Tab dirty-dot (`f.content !== f.saved`) and `SearchPopup`'s unsaved-files list now lag up to ~200ms behind typing. Save itself does not lag.
- No unsaved-changes-on-close prompt existed before this change and none was added — closing a tab still silently discards edits, same as before.
- The `beforeunload` flush only moves the pending edit into React state before the window closes; there is no autosave, so nothing is written to disk on quit — same as before my change. It's state hygiene (keeps `files` consistent), not new data protection.
- Considered keying the tab-switch/unmount flush effect on `activePath + diffFlag` (to catch the "Clear diff" remount generically) but that risks a `registerView`/`unregisterView` ordering race against CodeMirror's own remount; flushed explicitly in the "Clear diff" click handler instead, which is narrower and doesn't touch that machinery.
